# E2: how many bytes per round?

Generated by `npm run e2` on 2026-09-28: 13th Gen Intel(R) Core(TM) i5-13450HX (16 threads), win32 10.0.26200, Node v22.10.0, OpenSSL 3.0.15+quic. Run time 152.7 s.

Group of 200 meters, 10 rounds per row, t = floor(k/2) + 1 (t barely changes sizes). Messages are counted in a fixed-width encoding: ids and rounds 4 bytes, ring values 8, hashes and round secrets 32, Ed25519 signatures 64, MAC tags 16, Shamir shares 33 (49 once sealed). Announced sets (U, F, and an unmask request when a meter in F goes silent) are bitmaps over the anchored roster, 29 bytes each at N = 200. Means per meter per round, over the meters that reported.

A report alone is 32 bytes (id, round, 64-bit masked value, 16-byte tag). Paillier's report carries a 256-byte (1024-bit key) or 512-byte (2048-bit key) ciphertext instead of the 8-byte value (E1). With no dropouts a release is the round secret alone; the self-mask shares a meter received at confirmation are passed on only when a meter in F goes silent (the unmask column).

## What grows with N

## Setup, once per epoch

Each meter sends its signed epoch keys (1320 bytes, including a 1,184-byte ML-KEM key) and an ML-KEM encapsulation (1164 bytes) to each neighbour with a higher id, and receives its k neighbours' keys, their encapsulations, the roster (id and device key per member, needed to recompute the graph) and the anchor. Averages over a meter's neighbours, half of which have a higher id.
